# Requirements: feat-token-opt-t1

> Created: 2026-04-23 | Author: Hector Curbelo Barrios <hcurbelo@gmail.com>
> Feature: Token optimization Tier 1: default changes

## Problem

LLM tokens are getting expensive. An audit of sdd-kit showed that the real token cost is concentrated in `sdd spec refresh` — both when run manually and, more insidiously, when auto-triggered after every `sdd spec execute`. Today:

- `sdd spec create` defaults to level 3 (requirements + design + tasks), creating a `design.md` most users never fill — but its presence inflates downstream context (refresh, arch).
- `sdd spec execute` auto-refreshes every module with any changed file, even pure modifications that don't change module shape. The `hasStructuralChange` signal already exists in `git-changes.js` but isn't used as a gate.
- `sdd spec refresh` caps output at 2000 tokens per module with no way to opt into a leaner budget.

## Goals

1. Reduce default ceremony: `sdd spec create` defaults to `-2` (requirements + tasks); `-3` opt-in for complex features.
2. Cut ~50% of post-`execute` Claude calls by only auto-refreshing modules when structural changes are detected, with user override.
3. Reduce per-module refresh output by ~50% by lowering the default `max_tokens` from 2000 → 1000, with `--verbose` to restore 2000.
4. Keep all changes backward-compatible for existing scripts: `-3` still works, `--refresh=auto` preserves old behavior.

## Acceptance criteria

- `sdd spec create "foo"` with no size flag creates only `requirements.md` and `tasks.md`.
- `sdd spec create "foo" -3` still creates all three files.
- `sdd spec execute <spec>` with a task that only modifies existing files does not trigger module refresh.
- `sdd spec execute <spec> --refresh=auto` restores the previous "refresh on any change" behavior.
- `sdd spec execute <spec> --refresh=off` never triggers module or steering refresh.
- `sdd spec refresh` produces specs capped at 1000 tokens by default.
- `sdd spec refresh --verbose` caps at 2000 tokens (old default).
- `npm test` passes, including new tests covering the default level and refresh modes.
- CLAUDE.md template generated by `sdd init` and README.md reflect the new defaults.

## Out of scope

- Content-hash dedup for refresh (Tier 2 — separate PR).
- Scanner symbol extraction, `init --auto` parallelization, doc fixes (Tier 3/4).
- Version bump — maintainer decides at merge time.
