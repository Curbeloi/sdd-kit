# Requirements: feat-token-opt-t2

> Created: 2026-04-23 | Author: Hector Curbelo Barrios <hcurbelo@gmail.com>
> Feature: Token optimization Tier 2: hash-based refresh dedup

## Problem

Even after Tier 1's gating, `sdd spec refresh` still makes one Claude call per module every time it runs — regardless of whether the source files actually changed. For a project with 5-10 modules run routinely, this is the single biggest source of ongoing token spend.

## Goal

Add a content-hash dedup layer so `refresh` only calls Claude for modules whose source code has actually changed. Use an on-disk cache keyed by `mtime` to avoid re-hashing files that have not been touched.

## Design

- **Per-file hash cache** at `.sdd/cache/hashes.json`, indexed by path. Each entry records `{ mtime, size, sha1 }`. On `getFileHash`, if mtime+size match the cached entry, reuse the stored sha1 — no file read. Otherwise read, hash, update entry.
- **Group hash** per module: `sha1(sorted(["<path>:<sha1>", ...]).join("\n"))`. Order-independent via sorting.
- **Frontmatter on module specs**: each `<label>.spec.md` generated by refresh gets YAML frontmatter with `source_hash` and `generated_at`. On subsequent runs, if the newly computed `group_hash` matches the stored `source_hash`, skip the Claude call.
- **Escape hatch**: `sdd spec refresh --force` (`-f`) regenerates every module regardless of the cached hash.
- **Hygiene**: `sdd init` appends `.sdd/` to the consumer project's `.gitignore` (if one exists); `.sdd/` is also gitignored in this repo.

## Acceptance criteria

- Running `sdd spec refresh` twice in a row without touching any source file triggers zero Claude calls on the second run (all modules skipped).
- Modifying a single source file in one module causes only that module to be regenerated; others stay cached.
- `sdd spec refresh --force` regenerates every module, ignoring cached hashes.
- `sdd spec refresh src/core` uses the cache correctly (single-module path).
- `touch src/core/foo.js` without changing content invalidates the mtime cache entry, but the recomputed content-hash matches, so the group hash is unchanged and the module is still skipped.
- Deleting `.sdd/cache/` forces everything to be re-hashed from disk on the next run (no crash).
- Generated `<label>.spec.md` starts with a YAML frontmatter block containing `source_hash` and `generated_at`.
- `sdd init` appends `.sdd/` to the consumer project's `.gitignore` if not already present; existing `.gitignore` lines are preserved.
- `npm test` passes, including new tests for `hash-cache` and the frontmatter parser.

## Out of scope

- Symbol-level summarization (Tier 3).
- Parallelization of `init --auto`, plantilla CLAUDE.md slimming, doc fixes (Tier 4).
- Version bump — maintainer decides at merge.
